08 — Data & Security

Config stays local, changes are backed up

Local Data & Security

Encrypted passwords, recoverable deletes

Complete Linux / macOS build guide Distro dependency commands, AppImage / deb / dmg packaging, desktop icons, FUSE handling, and common error fixes. ▾

Linux x64 (AppImage / .deb / tar.gz)

System library package names vary by distro; Ubuntu 24.04 and later use *t64. The three outputs differ: AppImage needs no install, deb uses package management, and tar.gz runs after extraction without FUSE.

Compatibility: AppImage runs only on systems with glibc no older than the build machine. For 20.04–26.04 compatibility, build on the oldest Ubuntu 20.04; the repository's scripts/build-linux.sh detects the distro and handles t64 package fallbacks.
Don't want to install dependencies manually? Runbash scripts/build-linux.sh — one command handles detect distro → install system deps → choose package type → package → offer install, with apt / dnf / pacman support. For dependencies only, use ... deps; for diagnostics, use ... check; for a broken environment, use ... repair. During install: deb uses apt install and creates desktop icons; AppImage is copied to ~/Applications/LIULI-Shell with an app menu entry and desktop icon.

Run & install

chmod +x dist/LIULI-Shell-*-x86_64.AppImage
./dist/LIULI-Shell-*-x86_64.AppImage

# Install the deb on Debian / Ubuntu
sudo apt install ./dist/LIULI-Shell-*_amd64.deb

# Extract and run (no FUSE, no system directories)
mkdir -p ~/Applications
tar -xzf dist/LIULI-Shell-*-x86_64.tar.gz -C ~/Applications
~/Applications/LIULI-Shell-*/liuli-shell

AppImage error: dlopen(): error loading libfuse.so.2

AppImage uses the type-2 runtime and needs FUSE 2. Ubuntu 22.04 and earlier include it; 24.04 / 26.04 require manual installation. You can also extract and run without FUSE.

# Ubuntu 24.04 / 26.04
sudo apt install -y libfuse2t64
# Ubuntu 20.04 / 22.04, Debian 12
sudo apt install -y libfuse2

# Run without FUSE (slower start, same features)
./LIULI-Shell-*-x86_64.AppImage --appimage-extract-and-run

# Or use the tar.gz build, which needs no FUSE
Add app menu / desktop icons (AppImage) 
# 1) Put it in a fixed location
mkdir -p ~/Applications
cp dist/LIULI-Shell-*-x86_64.AppImage ~/Applications/LIULI-Shell.AppImage
chmod +x ~/Applications/LIULI-Shell.AppImage

# 2) Extract icons (--appimage-extract creates squashfs-root here)
cd /tmp && ~/Applications/LIULI-Shell.AppImage --appimage-extract '*.png' >/dev/null 2>&1
mkdir -p ~/.local/share/icons/hicolor/512x512/apps
cp /tmp/squashfs-root/*.png ~/.local/share/icons/hicolor/512x512/apps/liuli-shell.png 2>/dev/null \
  || cp /tmp/squashfs-root/liuli-shell.png ~/.local/share/icons/hicolor/512x512/apps/ 2>/dev/null

# 3) Write the desktop entry ($HOME expands to your home dir)
mkdir -p ~/.local/share/applications
cat > ~/.local/share/applications/liuli-shell.desktop <<EOF
[Desktop Entry]
Type=Application
Name=LIULI Shell
Comment=Cross-platform SSH terminal and server manager
Exec=$HOME/Applications/LIULI-Shell.AppImage %U
Icon=liuli-shell
Terminal=false
Categories=Development;System;Network;
StartupWMClass=LIULI Shell
EOF
chmod +x ~/.local/share/applications/liuli-shell.desktop
update-desktop-database ~/.local/share/applications 2>/dev/null || true

# 4) For a desktop icon, copy it and mark it trusted
cp ~/.local/share/applications/liuli-shell.desktop ~/Desktop/
gio set ~/Desktop/liuli-shell.desktop metadata::trusted true 2>/dev/null || true
# On localized systems the desktop folder may have a different name; adjust as needed

.deb users can skip these steps; installation writes /usr/share/applicationsautomatically and the app appears in the menu.

4. Package(Fastest for the current architecture; for both, pass dist:mac)

npx electron-builder --mac dmg zip --arm64    # Apple Silicon only

5. Output and cache:Output goes to ~/liuli-shell/dist/(*.dmg,*.zip); Electron and packaging tool downloads are cached in ~/Library/Caches/electron/and~/Library/Caches/electron-builder/; delete it to force a re-download.

6. Unsigned install:If Gatekeeper blocks the app after dragging it to Applications, right-click and choose Open, or run:

xattr -dr com.apple.quarantine "/Applications/LIULI Shell.app"
spctl --assess --type execute -vv "/Applications/LIULI Shell.app"   # check why it was blocked

Public distribution needs an Apple Developer ID certificate and notarization: set CSC_LINK(.p12 path or base64),CSC_KEY_PASSWORD; notarization also needs APPLE_ID,APPLE_APP_SPECIFIC_PASSWORD,APPLE_TEAM_ID; electron-builder handles signing and notarization.

Intel and Apple Silicon artifacts are not interchangeable. To cover both with one build, use npx electron-builder --mac dmg --universal(about twice the size of a single-architecture build, and noticeably slower).

Common error reference

Error / symptomCause / fix
Unable to locate package libasound2 Ubuntu 24.04 / Debian 13 renamed system libraries *t64(e.g. libasound2t64,libgtk-3-0t64). Install the old name first; fall back automatically:bash scripts/build-linux.sh deps has this logic built in.
dlopen(): error loading libfuse.so.2 AppImage needs FUSE 2 at runtime: on 24.04+ install libfuse2t64, and on 22.04 or earlier libfuse2; without FUSE, use --appimage-extract-and-run, or switch to .tar.gz.
Electron download times out / stuck at downloading Set a mirror and retry:export ELECTRON_MIRROR=https://registry.npmmirror.com/-/binary/electron/,export ELECTRON_BUILDER_BINARIES_MIRROR=https://registry.npmmirror.com/-/binary/electron-builder-binaries/.
npm ci fails / lockfile mismatch Delete node_modules and use npm install; Node below 18 won't install—use Node 20.
rpmbuild not found Only needed for rpm: on Fedora install rpm-build; on Debian/Ubuntu install rpm and rpm2cpio packages, or skip the rpm target.
Permission denied (running AppImage) Missing execute permission:chmod +x dist/LIULI-Shell-*-x86_64.AppImage.
errSecInternalComponent / signing failed (macOS) keychain is locked:security unlock-keychain -p <password> ~/Library/Keychains/login.keychain-db then rerun; on CI also security set-key-partition-list.

General notes

  • Build output:All artifacts go to the project root's dist/by default. Linux outputs LIULI-Shell-*-x86_64 / *-arm64 / .AppImage / .deb (the script detects the architecture); macOS outputs .tar.gz/ .dmg . .zip.
  • Before packaging:npm run vendor copies xterm.js and other frontend assets to src/renderer/vendor/; without this step the packaged terminal is blank.
  • Build machine:AppImage runs only on systems with glibc no older than the build machine. For 20.04–26.04 compatibility, build on Ubuntu 20.04; for personal use, build locally.
  • Cross-building:Linux packages build on Linux and macOS packages on macOS; outputs are not interchangeable, and the same applies to Windows. Use OS-specific CI (e.g. ubuntu-22.04,macos-14 runners) to build.
  • Publishing:Upload dist/ installers and portable builds as Release assets (Windows *.blockmap is only for delta updates—don't upload it); don't commit node_modules/ and dist/.
